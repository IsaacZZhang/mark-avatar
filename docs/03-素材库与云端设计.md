# 03 · 素材库与云端设计

## 1. 素材库总览

素材库是这个产品的**内容资产**，也是唯一的运营抓手。设计目标是：**运营改一个 JSON 就能上新，用户无感知更新，且首屏不等网络**。

```
                    ┌─────────────────────────────┐
   运营侧            │  云存储 /manifest.json      │  ← 素材清单（版本号 + 分类 + 元数据）
   （不发版上新）     │  云存储 /assets/*.png       │  ← 素材透明图（自带 CDN 加速）
                    └──────────────┬──────────────┘
                                   │ HTTPS（域名已在白名单）
                    ┌──────────────▼──────────────┐
   小程序端          │  ① 启动时拉 manifest（带版本号比对）
                    │  ② 版本未变 → 直接用本地缓存（首屏 0 等待）
                    │  ③ 版本变了 → 静默更新清单，素材图按需下载
                    │  ④ 素材图落盘到 wxfile:// 缓存目录，二次打开秒开
                    └─────────────────────────────┘
```

## 2. 素材清单数据模型

```json
// cloud://xxx/manifest.json
{
  "manifestVersion": 17,
  "updatedAt": 1738000000,
  "categories": [
    { "id": "funny",    "name": "搞怪", "icon": "cloud://.../icon_funny.png", "sort": 1 },
    { "id": "festival", "name": "节日", "icon": "cloud://.../icon_fest.png",  "sort": 2 },
    { "id": "sports",   "name": "赛事", "icon": "cloud://.../icon_spo.png",   "sort": 3 },
    { "id": "mood",     "name": "心情", "icon": "cloud://.../icon_mood.png",  "sort": 4 }
  ],
  "templates": [
    {
      "id": "sold_out_v1",
      "name": "卖掉了",
      "category": "funny",
      "type": "sticker",
      "asset": "cloud://env/assets/funny/sold_out.png",
      "cover": "cloud://env/assets/funny/sold_out_cover.png",
      "layout": { "cx": 0.5, "cy": 0.84, "scale": 0.78, "rotate": -8, "opacity": 0.95 },
      "tags": ["二手", "闲置换钱", "搞笑"],
      "builtin": true,
      "needUnlock": false,
      "unlockAdUnit": "",
      "sort": 100
    }
  ]
}
```

字段说明：

| 字段 | 作用 |
|------|------|
| `builtin: true` | 打进主包的 10 个首屏素材，离线可用，不依赖网络 |
| `layout` | 默认摆放位置（归一化坐标），用户点一下就出效果，不用手动调 |
| `needUnlock` | 是否需看激励视频解锁（二期变现） |
| `tags` | 搜索关键词（三期） |

> **`layout` 默认值很关键**。用户点素材的期望是"立刻好看"，如果每个素材都要手动摆位置，转化率会掉一大截。所以每个素材必须配好出厂位置，把调整做成可选项。

## 3. 缓存策略（三级）

| 层级 | 内容 | 介质 | 失效策略 |
|------|------|------|----------|
| L1 内置 | 10 个爆款素材图 + 兜底 manifest | 代码包 | 随版本更新 |
| L2 清单 | manifest.json | `wx.setStorageSync` | `manifestVersion` 比对 |
| L3 素材图 | 按需下载的 PNG | `FileSystemManager` 落盘 | LRU，上限 200 张 / 20MB |

```js
// services/template.js
const MANIFEST_URL = 'https://<env>.tcb.qcloud.la/manifest.json'; // 云存储默认域名，一键加白名单
const CACHE_KEY = 'wm_manifest';

async function loadManifest() {
  const local = wx.getStorageSync(CACHE_KEY);
  renderFromCache(local);                       // 先用缓存渲染，首屏不等网络

  try {
    const remote = await fetchJSON(MANIFEST_URL);   // 带超时 3s，失败静默降级
    if (!local || remote.manifestVersion > local.manifestVersion) {
      wx.setStorageSync(CACHE_KEY, remote);
      renderFromCache(remote);                  // 增量刷新 UI
    }
  } catch (e) {
    // 网络失败就用缓存，工具型小程序绝不能因为网络差打不开
    report('manifest_fetch_fail');
  }
}
```

**设计要点**：采用 **stale-while-revalidate**。先渲染缓存保证秒开，网络返回后静默替换。网络挂了也能用，这对工具型小程序的留存影响很大。

## 4. 云开发资源设计

### 云函数（5 个，都很薄）

| 云函数 | 职责 | 触发时机 |
|--------|------|----------|
| `reportUsage` | 素材使用次数 +1、保存成功 +1、分享 +1 | 用户操作后异步上报，不阻塞 UI |
| `secCheck` | 云调用 `msgSecCheck` / `imgSecCheck` | 用户提交自定义文字或 UGC 素材时 |
| `getWxacode` | 云调用 `getwxacodeunlimit`，生成带 `scene` 的小程序码 | 分享卡片合成时（结果缓存到云存储，按 scene 复用） |
| `unlockAsset` | 校验激励视频完成态，写入解锁记录 | 看广告后 |
| `getHotRank` | 返回素材热榜（按近 7 天使用量排序） | 素材中心「热门」tab |

> 为什么这些必须放云函数而不是端上：`msgSecCheck` 和 `getwxacodeunlimit` 是**服务端接口**，需要 access_token。云开发可以**免鉴权云调用**，省掉整套 token 管理。这是选云开发最实际的理由。

### 云数据库集合

| 集合 | 字段 | 用途 |
|------|------|------|
| `wm_stat` | `templateId`, `date`, `useCnt`, `saveCnt`, `shareCnt` | 热榜与运营决策（哪个素材该放首屏） |
| `wm_user` | `_openid`, `firstAt`, `lastAt`, `saveCnt`, `unlocked[]` | 留存分析、解锁记录 |
| `wm_ugc` | `_openid`, `assetFileID`, `status(pending/pass/reject)`, `likeCnt` | 三期 UGC 审核队列 |
| `wm_share` | `scene`, `openid`, `pv`, `uv` | 裂变归因 |

### 云存储目录

```
/assets/{category}/{templateId}.png      # 素材透明图
/covers/{category}/{templateId}.png      # 选择器缩略图
/qrcode/{sceneHash}.png                  # 分享小程序码（生成一次永久复用）
/manifest.json                           # 素材清单
```

## 5. 埋点设计

不做无用埋点，只采集驱动决策的 5 个：

| 事件 | 关键参数 | 用来回答什么问题 |
|------|----------|------------------|
| `app_launch` | scene, 是否新用户 | 流量从哪来 |
| `pick_image` | source=avatar/album | 用户到底用头像还是相册（决定 D2 资源投入） |
| `apply_template` | templateId, 是否首次 | 哪些素材受欢迎 |
| `save_image` | templateId, 耗时 ms, 是否成功 | 核心转化 + 性能监控 |
| `share` | type=friend/timeline, scene | 裂变系数 |

**核心北极星指标**：`日保存成功次数 / 日活`（目标 > 60%）。低于这个值说明编辑链路有摩擦。

## 6. 接口预留（为将来接自建后端留口子）

`services/cloud.js` 里统一封装，将来要把某个能力迁到自建 Go 服务，只改这一层：

```js
// services/cloud.js
const IMPL = {
  cloud,      // 当前：云函数
  // http     // 未来：自建后端，域名已在 request 白名单
};
async function call(name, data, { timeout = 3000, fallback = null } = {}) { ... }
```

所有调用都带 `timeout` + `fallback`，**任何后端失败都不能阻塞出图**。工具型小程序最忌讳"网络转圈导致用不了"。
