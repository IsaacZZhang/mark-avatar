# 头像水印小程序 · 架构设计

**仓库**：https://github.com/IsaacZZhang/mark-avatar · **协议**：MIT · **主体**：个人（业余项目）

> 目标：快速上线 + 快速获客。一句话定义产品——**"30 秒内给头像加一个有趣的角标，一键换回微信头像"**。
> 设计原则：**端侧完成全部图像处理，云只做素材分发与数据统计**。这样主包小、响应快、无后端运维，素材还能不发版热更。

## 核心链路（一眼看懂）

```
用户进入 → 选图（微信头像 / 相册）
        → 选水印（预设素材库，分类浏览）
        → 实时预览（Canvas 2D 渲染，可拖拽缩放旋转）
        → 一键保存（导出 1080px JPEG → 存相册）
        → 顺手更换微信头像 / 分享给好友
```

**唯一的技术核心**：一个可靠的 **Canvas 2D 分层合成引擎**。其余都是素材运营和增长玩法。

## ⚠️ 需要你拍板的 5 个决策点

下面是会直接改变架构走向的分叉口。我的推荐已标出，你回一句"按推荐"或改某项即可。

| # | 决策点 | 方案 A | 方案 B | 方案 C | 我的推荐 |
|---|--------|--------|--------|--------|----------|
| D1 | **后端形态** | **微信云开发**（云函数+云数据库+云存储+CDN，免备案域名免运维） | 纯前端零后端（素材全打包，更新必须发版） | 自建 Go/tRPC 后端（复用你现有栈，多 1~2 周） | **A**。上线最快、成本最低；素材热更与埋点都有落脚点 |
| D2 | **图片来源** | **微信头像 + 相册上传** | 仅微信头像 | 头像+相册+拍照 | **A**。不止做头像，顺带覆盖表情包/朋友圈配图，复用率高 3 倍以上 |
| D3 | **素材分发** | **内置 10 个爆款 + CDN 热更** | 全内置分包 | 全云端下发 | **A**。首屏秒开且运营可不发版追热点（节日/赛事 48h 上新） |
| D4 | **增长机制** | **作品角标小程序码 + 分享对比卡片** | 激励视频解锁精品水印 | UGC 素材社区 | **A 先做，B 二期，C 三期**。A 零成本且自带传播 |
| D5 | **水印内容边界** | **原创文案/通用梗图** | 复刻平台视觉（如"闲鱼卖掉了"原版 logo） | 用户自定义文字 | **A + C**。B 有商标风险，见下文红线说明 |

### 关于 D5 的额外提醒（重要）

"闲鱼卖掉了"这类水印如果**直接复刻品牌 logo / 商标 / 官方视觉元素**，小程序审核和后续投诉都有风险。建议做法是：

- ✅ 用**通用文案 + 自绘图形**：「卖掉了」「已出」「回血中」「断舍离」「不卖」——梗是那个梗，字和图自己画
- ✅ 走**原创素材 + 用户自定义文字**，自由度最高且零版权负担
- ❌ 不要用平台 logo、吉祥物、商标字体

这个不影响架构，但影响素材库的内容规范，需要在运营侧立规矩。

## 关键约束（已核实的微信平台现状）

| 约束 | 现状 | 应对 |
|------|------|------|
| **用户头像获取** | `wx.getUserInfo` / `wx.getUserProfile` 均已回收，返回灰色默认头像 + "微信用户" | 必须用 **头像填写能力**：`<button open-type="chooseAvatar" bindchooseavatar="...">`，回调 `e.detail.avatarUrl` 是临时文件路径 |
| **图片合成** | 老版 `CanvasContext` + `ctx.draw` 已过时 | 用 **`type="2d"` 新 Canvas**，`createSelectorQuery` 拿 node，`canvas.createImage()` 加载图 |
| **保存相册** | 需 `scope.writePhotosAlbum`，用户拒绝后再次调用直接 fail | 失败后引导 `wx.openAppAuthorizeSetting` 去设置页 |
| **包名/体积** | 主包 ≤ 2MB，总包 ≤ 20MB | 素材全部走 CDN，主包只留代码 + 10 张首屏素材 |
| **合法域名** | `downloadFile` 域名需在后台配置 | 云存储域名可一键加入白名单，几乎零成本 |

## 开源与素材版权（公开仓库必读）

代码 MIT 开源，但**素材和代码是两回事**，这里说清楚边界：

| 内容 | 是否进仓库 | 说明 |
|------|-----------|------|
| 引擎 / 页面 / 配置代码 | ✅ 进 | MIT，随便用 |
| 占位素材（`assets/stickers/*.png`） | ✅ 进 | 脚本生成的通用文案，无版权问题 |
| **正式设计素材** | ⚠️ **建议不进** | 见下 |

**好消息是架构天然支持素材不入库**：素材的热更链路走云存储 CDN，`manifest.json` 里只存 URL，仓库里不需要放图。所以：

- 仓库里只保留 8~10 个**内置兜底素材**（保证断网可用、也方便别人 fork 后直接跑）
- 你精心设计的正式素材放云存储，通过远程清单下发 —— **既不进公开仓库，又能不发版上新**

这样「代码开源」和「素材不外流」两全。如果哪天确实想把正式素材也开源，换掉文件名覆盖即可。

**另外三条安全红线**（`.gitignore` 已配好，别手动 `git add -f`）：

1. `private.key`（小程序上传密钥）—— 泄露等于别人能替你发版
2. `AppSecret` / 云开发密钥 / 任何 `.env`
3. `project.private.config.json`（你的 AppID 填这里，就不会进版本库）

> 补充：`AppID` 本身不算机密（小程序码里就含），但既然是公开仓库，还是建议用 `project.private.config.json` 隔离，让别人 fork 后填自己的。
